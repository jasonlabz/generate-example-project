## 4. TASK-01 文件地图与原子 TDD 步骤

**目标与非目标：** 将 Health Check Controller 改为模块目录，保留 Service 所有的接口并以构造函数注入；让领域结果经 convertor 映射为 HTTP DTO；提供 Controller、Service、Manager 的 GoMock 单元测试样例。不得改变对外 HTTP/OpenAPI/Knife4go 行为，不引入通用 DI 容器或额外抽象层。

**文件地图（均相对仓库根）：**

- `ADD`: `server/controller/health_check/register.go` — 导出 `HealthCheckController` 与 Huma 路由/操作注册。
- `ADD`: `server/controller/health_check/controller.go` — 私有实现、构造函数、注入的 `service.HealthCheckService` 与处理编排。
- `ADD`: `server/controller/health_check/types.go` — HTTP 输出 DTO 与模块常量。
- `ADD`: `server/controller/health_check/convertor.go` — `service.HealthCheckResult` 到 HTTP 输出 DTO 的纯转换。
- `ADD`: `server/controller/health_check/controller_test.go` — 以 `MockHealthCheckService` 覆盖成功与 Service 失败的 HTTP 可观察行为。
- `ADD`: `server/controller/health_check/convertor_test.go` — 覆盖领域结果到响应 `data` 的纯映射；不使用 Mock。
- `ADD`: `server/controller/health_check/README.md` — 记录四个生产文件的职责、依赖方向、接口归属理由、composition root 与三层测试样例。
- `MOD`: `server/service/health_check.go` — 在 Service 契约旁定义最小 `HealthCheckResult`，将 `Check` 改为返回结果与错误。
- `MOD`: `server/service/health_check/health_check_impl.go` — Manager 成功时构造领域结果，失败时保留 `%w` 错误上下文。
- `MOD`: `server/service/health_check/health_check_impl_test.go` — 以 `MockHealthCheckManager` 同时断言成功结果和错误包装。
- `MOD`: `server/router/router.go` — 改用新 Controller 模块包；保留当前唯一 composition root 和 Huma 配置。
- `MOD`: `server/mocks/generate.go` — 将 Controller Mock 的源包改为 `server/controller/health_check`。
- `GEN`: `server/mocks/mock_service.go`、`server/mocks/mock_controller.go` — 由 `go generate ./...` 生成，禁止手改。
- `DEL`: `server/controller/health_check.go`、`server/controller/health_check_test.go` — 由对应模块文件取代，不保留兼容包装。

**原子 TDD 步骤：**

1. 修改 Controller/Service 测试，使成功 Mock 返回 `service.HealthCheckResult{Status: "success"}`，并新增 convertor 的结果映射断言。执行 `go test ./server/controller/health_check ./server/service/health_check`；预期 RED：旧接口不存在结果返回值，且新模块包/convertor 未定义。
2. 最小实现 Service 结果契约、Service 成功返回值和 Controller 模块文件；保留 `humax.InternalServerError("v1", err)` 作为错误适配边界。执行同一命令；预期 GREEN：Controller 成功、Controller 失败、convertor 和 Service 分支均通过。
3. 更新 Router 导入与 Mock 生成声明，执行 `go generate ./...`；预期 GREEN：生成物签名及 Controller Mock 来源均与新接口一致。
4. 运行 `go test ./server/manager/health_check ./server/router`；预期 GREEN：Manager Probe 成功/失败和 Router 的 HTTP/OpenAPI 文档契约不回归。
5. 运行完整回归：`go test ./...`、`go test -race ./...`、`go vet ./...`、`go build ./...`、`git diff --check`；预期均为 PASS。`go test -cover ./server/controller/health_check ./server/service/health_check ./server/manager/health_check` 只用于报告关键分支是否被执行，不以数字驱动添加无价值测试。

**关键测试覆盖：**

- Controller：请求成功的状态码/包络/无 Link；Service 错误映射为既有 500 包络。
- Service：调用 Manager 成功时返回 `Status: "success"`；Manager 失败可由 `errors.Is` 找到原始错误。
- Manager：调用 Probe 成功与失败（沿用既有 `MockHealthProbe` 测试）。
- Router：精确保留四个 legacy 顶层字段、拒绝 `$schema` 和 `Link`，并保留 Knife4go OpenAPI 3.0.3 可用性。
