# GoMock 生成脚本优化设计

## 目标

将 `script/go-mockgen.sh` 优化为可按路径选择源码、按相对路径生成 mock 的项目级工具。默认输出目录为 `server/mocks`，并继续兼容 Windows Git Bash 与 Go `internal` 包的导入可见性规则。

## 范围与约束

- 支持 `-p path1,path2,...`，默认扫描项目根；每个路径必须位于项目根内。
- 支持 `-o output-root`，默认值为 `server/mocks`；输出目录必须位于项目根内。
- 支持 `-s strip-prefix`，从普通源码的项目相对路径开头去除一个完整目录前缀后再镜像。
- 调用 PATH 中的 `mockgen`；缺失时给出安装提示并以非零状态退出。
- 扫描跳过 `*_test.go`、`*.gen.go`、`vendor`、`.git`、`.mocks` 及当前输出目录。
- 仅为声明导出顶层 interface 的源码生成 mock，避免外部 mock 包引用私有类型而无法编译。
- 不提交本设计文档或后续改动，除非用户另行要求。

## 生成与清理规则

脚本先校验并规范化输入路径，再让 Go 扫描器按给定源码根输出项目相对路径。对于普通包，输出文件为：

```text
<output-root>/<strip 后的源码目录>/mock_<源码文件名>.go
```

每次运行先在输出根中清理带 `Code generated by MockGen` 标记的 `mock_*.go`，不删除输出目录、README 或其他手写文件。内部包重定向到 `.mocks/` 时，只在同源文件重新生成前覆盖其对应目标，不扫描或删除其他 `.mocks/` 目录。这样既消除常规输出中已删除接口留下的生成物，也避免 `rm -rf -o` 的误删风险。

## internal 包规则

普通路径镜像一旦使 mock 包位于被测 `internal` 包父目录之外，就不能合法导入该包。脚本会为这类源码把 mock 放在对应 internal 父树内的 `.mocks/`，并打印该重定向路径；这是唯一允许不落在 `-o` 内的情形。

如果用户明确把输出根放在同一 internal 父树内，例如：

```shell
bash script/go-mockgen.sh \
  -p internal/dao/interfaces,internal/manager/interfaces \
  -o internal/mocks \
  -s internal
```

则输出直接落在 `internal/mocks/...`。`-s` 只匹配完整的项目相对路径前缀，不做任意字符串替换。

## 接口与模块边界

- `go-mockgen.sh` 负责参数解析、环境检查、路径映射、清理和调用 `mockgen`。
- `script/internal/mockscan` 负责安全地发现候选 Go 源文件；新增源码根参数与 `*.gen.go` 排除，不负责生成或删除文件。
- 生成物统一使用 `mocks` 包名，以保持现有测试导入方式稳定。

## 错误处理

- 未知参数、缺少参数值、项目外路径、空路径列表均打印用法并退出。
- 不存在的 `-p` 路径输出跳过提示；全部路径无效则失败。
- `mockgen` 不在 PATH 时显示 `go install go.uber.org/mock/mockgen@latest` 提示。
- 扫描或单文件生成失败立即退出；已生成的文件保持可见，便于定位失败点。

## 测试与验收

扩展 `script/go_mockgen_test.go`，使用临时源码树与受控的 mockgen 测试替身验证：

1. 默认输出为 `server/mocks`，`-p` 只扫描指定源码根。
2. `-s internal` 正确去除完整前缀。
3. `*_test.go`、`*.gen.go` 和输出目录中的源码不会再次被扫描。
4. 仅清理带 MockGen 标记的 mock 文件，README 与无标记文件保留。
5. 嵌套 `internal` 源码重定向到合法的 `.mocks/` 路径。
6. 缺失 `mockgen` 时返回清晰错误。

验证命令为 `go test ./script`，以及项目全量 `go test ./...`。
